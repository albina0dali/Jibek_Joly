# JibekJoly

## Acceptance audit и интерфейс центра управления

[Проверка исходных условий и ограничения](docs/CASE_ACCEPTANCE_AUDIT.md) отделяет реальные вычисления и проверки от simulated data. Полного единого runtime между Core (6 поездов) и Python (16 поездов) нет: общий реестр и формула индекса не означают общее расписание. Поэтому incident основной карты не является incident F103 в Python-плане.

Навигация сгруппирована в «Операции», «Интеллект / анализ», «История», «Система». Раздел `#ato` — **Автоведение** (KK: **Жылдамдық профилі**); Eco-driving обозначает benefit/режим модели. Компактные KPI рассчитываются из текущего state. Шапка показывает источник, clock и ID поездки либо revision расписания; Python last update доступен в подсказке соединения. Preview выделен синим, Apply применяет проверенное расписание. CSV теперь содержит отдельные строки `summary,movement-index` и `summary,simulation-time`.

UI target — 1366×768; проверены также 1920×1080 и 390×844. Before/after: `.jol-local/ui-review/`. Дополнительная проверка при запущенном `npm start`: `npm run test:ui` (core incident, сбой запроса/reconnect, RU/KK и темы). Ограничения latency <500 ms, end-to-end replan ≤5 s и burst/load: **NOT MEASURED**.

## Оперативная карта

Раздел `#map` называется «Оперативная карта» (KK: «Операциялық карта»). Внутри доступны «3D Обзор сети» и «2D Диспетчерская схема»; отдельного пункта навигации для 2D нет. Обе проекции используют одно состояние девяти канонических станций, поездов, путей, сигналов и общего индекса движения. Переключение не сбрасывает поездку. Английская локаль в приложении отсутствует.

2D-схема показывает позиции и направления поездов, задержки, основной и резервный пути, занятость и сигналы. Выбор поезда и участка использует существующий пульт; станция открывает прибытия. Нажатие сигнала выполняет ту же команду, что и в 3D. Во время replay команды сигналов недоступны. На узком экране схема прокручивается внутри панели. Проверка: `npm run test:map` при запущенном `npm start`.

## Интегрированные страницы

Общая навигация содержит `#movement-plan` (План движения), `#history-reports` (История и отчёты), `#wagons-consists` (Вагоны и составы). Старые `#plan` и `#history` сохранены как «Диспетчерская» (прогноз шести вариантов) и «Записи поездок» (полные поездки). Все страницы используют общий shell, RU/KK, тему и CSS tokens.

Командная модель (9 станций, 6 поездов) сохранена. Расширение использует `data/extensions/operations`: 8 станций общего реестра, 14 блоков, 16 поездов, 120 вагонов, 4 пути, 2 маневровых локомотива. Источник — сохранённый `integration_handoff_bundle`, synthetic seed 42. [Реестр девяти станций и явное соответствие](docs/STATION_MAPPING.md) воспроизводятся командой `node scripts/build-station-registry.mjs`. Перенесены сами station IDs во всех наборах данных. **Synthetic operational corridor distance** — 164 км условного масштаба; это не географическое расстояние. Алматы-1 — условный узел SIMULATED YARD OPERATIONS.

React используется только внутри трёх новых страниц. Исходные Python scheduler, независимый validator, CP-SAT yard и ReportLab сохранены в `server/extension`. Worker предоставляет авторизованный same-origin namespace `/api/extension/*`; старые API/D1 не изменены. Preview и replay не изменяют LIVE, Yard Apply не создаёт поезда коридора. CSV/PDF всегда экспортируют текущий LIVE traffic, включая экспорт во время replay; yard inventory туда не входит.

Единый пользовательский «Индекс движения», `I = Σ(score × weight / 100)`, использует веса 30/20/20/20/10 и общую спецификацию `web/movement-index-model.json` в JavaScript и Python. [Формула, адаптеры и ограничения](docs/MOVEMENT_INDEX.md). Baseline расширения — **91,1**; задержка F103 на 600 секунд снижает его до **74,0**, проверенный Apply возвращает **91,1**. Legacy score сохранён только внутри для совместимости. Yard baseline: 12 составов, 120,48 вагоно-часа; рассчитанный feasible план — 8 составов, 114,48 вагоно-часа. Optimality не обещается.

`npm start` запускает Python на 127.0.0.1:8001 и существующий Worker/D1 на 8787. SQLite расширения находится в `.jol-local/extension.sqlite`; один Python worker держит отдельное mutable demo state. При перезапуске history и yard results сбрасываются согласно исходному lifecycle. На Linux создайте venv командой `python3.12 -m venv .jol-local/extension-venv` и установите тот же lock через `.jol-local/extension-venv/bin/python`.

Cloudflare Worker не выполняет Python/OR-Tools. Для размещения нужен отдельный Python-сервис и Worker binding `EXTENSION_URL` (доверенный HTTPS origin). Для приватного сервиса задайте одинаковый `EXTENSION_SERVICE_KEY` в Python и Worker; настройте `DISPATCHER_PASSWORD` в Python и `EXTENSION_DISPATCH_PASSWORD` в Worker. Не открывайте демо-сервис с исходными паролями публично. Локально эти bindings устанавливаются автоматически; production deployment в рамках интеграции не выполнялся. Без сервиса старые страницы работают, новые выводят понятную ошибку 503. `EXTENSION_PYTHON` позволяет указать путь к другому локальному Python; `EXTENSION_URL` позволяет подключить уже запущенный сервис.

## Демо

По умолчанию включена «Зелёная волна»: два направления по отдельным путям. SIM-FRT-208 начинает движение с 80 км/ч, до сигнала 7 модельных км, открытие в 08:10. Средняя целевая скорость — 42 км/ч; плавное замедление ведёт к крейсерской скорости около 38,7 км/ч. SIM-FRT-209 также проходит последовательность известных зелёных окон. Нажатие на светофор в 3D или панели включает ручной красный; повторное возвращает автоматическое управление. Все типы поездов соблюдают сигналы и занятость пути.

«Показать итог поездки» завершает оставшуюся симуляцию и сравнивает два полных прогона с одинаковыми данными, наблюдавшимися сбоями и командами диспетчера: меняется только Eco. Экономия выводится со знаком. Если поезд удержан или ручной красный не снят, незавершённому прогону не приписывается экономия.

Индекс рассчитывается по текущему состоянию: задержки, доля движущихся поездов, энергетический advisory proxy, конфликты и прогноз прибытия. Нормальное начало командной модели — около 90,7. Сбои и удержания снижают индекс. Это демонстрационная метрика, не точность ML.

## Данные и ограничения

`data/eco-package.json`: kz-eco-synthetic-v2, seed 20261002. Топология, километры, расписание, масса и параметры движения синтетические; это не данные ҚТЖ. Ускорение грузового состава 0,10 м/с², торможение 0,12 м/с² — условные параметры, не проверенные тормозные кривые. Система консультативная, не управляет реальными поездами.

Финальные литры — оценка некалиброванной демо-модели: 0,4 л на условную единицу энергетического proxy. Они не являются измеренным расходом дизеля. При исправном демо обе грузовые проходят четыре известных зелёных окна без остановок; в парном базовом прогоне по три остановки. Результаты вычисляются симулятором.
